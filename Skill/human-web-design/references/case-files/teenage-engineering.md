# Case file: Teenage Engineering

- **URL:** https://teenage.engineering/
- **Direction:** Industrial / Manual
- **Physical object it evokes:** a product manual and control panel
- **Analysed:** 2026-10-28

## Tokens

| Token | Value | Note |
|---|---|---|
| Fonts | Custom grotesk (te-20) mostly at weight **100**, plus a techno display face | Ultra-thin weight is the voice |
| Body | 16px / 24px, light grey `#f1f2f2` on black | |
| Type sizes in use | 9 · 12 · 16 · 17 · 19.5 · 35 | Lots of tiny label text (9px) |
| Colour | Monochrome; product photography supplies the only colour (orange/red details on hardware) | Signal colour like an LED |
| Radius | ~6px on few elements, otherwise square | |
| Borders | 1px mid-grey, rare | |

## Signature moves

1. **Nav as a control panel**: each top-level item has a line-drawn pictogram, a label, and 2–3 tiny sub-links underneath (e.g. "products — instruments, audio, designs").
2. **One dramatic product photograph** fills the viewport on black — the product is lit like an object in a studio.
3. **A block of small Japanese text** used as texture and brand voice in the header.

## Why it works

The site behaves like the hardware: precise, labelled, minimal. Thin type and tiny labels feel like silkscreened markings on a device. Photography is the hero because the product's design is the selling point.

## How to adapt

- Make the nav look like the product's own interface language.
- Use extremely light weights only at large sizes and high contrast; use tiny tracked labels as a second voice.
- Spend the budget on photography or a faithful product render.

## Watch-outs

- Weight-100 text fails accessibility at small sizes or low contrast — keep thin weights large.
- Works for objects with strong industrial design; for software, use real UI instead of photos.
